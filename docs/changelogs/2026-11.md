- Week key shows the real marks (a mini ringed cell for full day, green ★ for every goal met) instead of plain text.

## 16 Nov 2026: M0 scaffold + M1 first usable cut (local only)

- Build plan agreed: M0 scaffold → M1 This week/Settings/weigh-in → M2 game layer + History → M3 polish → M4 ship.
- `git init` (local, nothing committed). Node 24, Express 5.3, better-sqlite3 13.2 (prebuilt binary, no compiler),
  `"type": "module"`, tests on built-in `node:test` (15 passing: dates/DST/edit window, st/lb, scoring, API flows).
- DB: schema per design.md with numbered migrations via `PRAGMA user_version`; WAL mode, clean close on SIGTERM.
  Seeded starting targets: Intermittent fast 7/7, No snacks 7/7, Running (miles) 3/7, Weight training (min) 2/7.
- Small calls made while building (not design changes): `week.closed_at` dropped (a week is closed once a later
  Monday has started, computed); `goal_days` lives on `target` as the current definition and is copied into
  `week_target` snapshots; any target change re-snapshots the current week only; a target's kind can't change after
  creation; renames show everywhere (names aren't snapshotted); correcting a weigh-in keeps its original
  `entered_on`/late flag; a past week with no snapshot is only created when it's still editable.
- UI: This week (tap grid, custom number pad, N/7 pills, score bar, weigh-in in st/lb with change vs last week and
  late flag, goal progress bar, week navigation) and Settings (targets add/edit/reorder/retire/restore, goal weight,
  corrections mode). Light/dark via `prefers-color-scheme`. Checked at 360 px with headless Edge.
- Dockerfile (`node:24-slim`, `/data` volume, healthcheck). Not built locally (no Docker on the dev machine); the
  GHCR Action will build it.
